\## 4. Definition of Done



A task may be marked Done when:



1\. Its agreed work has been completed.

2\. The changes have been tested where applicable.

3\. Relevant documentation has been updated.

4\. The work has been committed to Git with a descriptive message.

5\. The team has reviewed or accepted the change according to its workflow.



\## 5. Team Workflow



1\. Agree on the task and its owner before starting work.

2\. Create a separate Git branch for a substantial change.

3\. Make small, meaningful commits.

4\. Push the branch and open a pull request when the team uses pull requests.

5\. Review and merge the change into the main branch.

6\. Update this backlog to reflect actual progress.



\## 6. Review Notes



This backlog is an initial plan, not a claim that all listed tasks have been completed. The team should revise task owners, priorities, and statuses as development progresses.
